## 版本历史

### v1.2.7（2026-11-11 · 更新中心 / 主版本与测试版双通道 / 最终开源版）

> 基线 v1.2.6。**这是最后一个开源版本**：此后的小步更新不再单独发包、不再同步源码，
> 统一由更新中心（`https://update.yuejiaxin.ln.cn`）自动分发，设备联网即收通知。
> 变更明细见 [docs/UPDATE-2026-11-11-v127.md](UPDATE-2026-11-11-v127.md) 与 [RELEASE-1.2.7.md](../RELEASE-1.2.7.md)。

- ✅ **更新系统**：独立「更新中心」服务（零依赖单文件，`systemd` 托管，nginx 反代到 `update.yuejiaxin.ln.cn`）。发布只登记版本号 + 更新说明 + 1~N 个下载直链（对象存储多地域），设备侧自动比对版本、多直链测速选最快、sha256 强校验、失败自动回滚。
- ✅ **主版本 / 测试版双通道**：`stable` 给生产设备、`beta` 给验证机；通道按设备存在 `system_configs`，同一中心可同时推两套版本。Beta 通道在没有 Beta 版时自动回落到稳定版最新。
- ✅ **检查更新页**：按版本逐条列出「这个版本改了什么」，由用户自己选择升级到哪一版；当前版本有独立说明区块；无可用更新时显示「当前已是最新版本」。下载直链不在前台展示。
- ✅ **侧栏版本提示**：发现新版本时左下角出现「新版本 x.y.z · 立即前往更新」，点击直达设置页；在线设备每 10 分钟自动比对一次，切回标签页立即复查。
- ✅ **更新中心后台**：管理页必须登录（Basic Auth），支持发布、设为最新、删除版本记录；删除 latest 后自动按稳定通道重算。
- ✅ **运行时安全修复**：更新脚本改用 `systemd-run` 启动，避免 `systemctl restart` 时按 cgroup 连脚本一起杀掉；测速改为按 `curl` 退出码判定，杜绝 404 被误判成「最快线路」。

### v1.2.5（2026-11-11 · 并发安全 / 备份回滚 / 日志留痕）

> 基线 v1.2.4。

- ✅ **并发扣库存竞态修复（P0）**：原「查 → 判断 → 写」改为单条带条件的原子 UPDATE（`SET on_hand = on_hand - ? WHERE id = ? AND on_hand - locked >= ?`），过账前先做原子状态抢占（`UPDATE ... SET status='POSTING' WHERE status IN ('DRAFT','APPROVED')`）。批次与货位扣减、库存锁定/解锁、调拨扣减、盘点结算同步改造。实测：库存 5 被 10 单争抢由「10/10 全成功、超卖 7 件」变为「恰 5 成功 5 拒绝」；同一单并发过账由「10 次全过」变为「1 次通过」。
- ✅ **数据备份与回滚**：手动/定时（每小时 / 每天 / 每周 / 自定义 Cron）备份数据库 + 上传文件 + 关键配置，默认保留 30 天可调，支持下载、恢复（恢复前自动生成安全备份）、删除、超期自动清理并保留最近一次成功备份。
- ✅ **日志清空留痕**：日志页按页签清理，需手输「清空日志」确认，清空动作本身写系统日志（操作人 / 时间 / 条数 / 范围）。
- ✅ **邮件模板中心**：报表订阅必须绑定模板，正文变量按白名单渲染，禁止「填段文字就订阅」。
- ✅ 侧栏版本号改为读取 `package.json`（不再硬编码），为自动更新打底。

### v1.2.2（2026-10-31 · 第三方深度测试整改：库存完整性 / 会话吊销 / 上传闭环 / 验证码）

> 基线 v1.2.1。来源：《云仓智能仓储管理平台 — 深度功能测试 + 安全评估报告》（2026-10-29 ~ 10-31）。
> 逐条整改 H1~H3 / M1~M7 / F1~F13 / L1~L7 / B1~B10，逐项对照见 [docs/UPDATE-2026-10-31.md](UPDATE-2026-10-31.md)。

#### 高危（数据完整性 / 会话）

- ✅ **FIX-2026-2011（P0）负数量单据**：入库/出库建单与过账双重校验 `qty > 0`、`单价 ≥ 0`、单行 ≤ 1e6、
  金额 ≤ 1e12；加权平均成本在 `onHand < 0` 时不再套公式（实测可把成本推到 22.5 亿且不可逆），
  改为按本次入库价重建基准成本并写 `COST_REBUILD` 审计。
- ✅ **FIX-2026-2012（P0）并发重复过账**：过账事务先 `SELECT ... FOR UPDATE` 锁单据行，
  收尾用条件更新 `updateMany({where:{id,status}})`，影响行数 0 → 409。5 连发只成功 1 次。
- ✅ **FIX-2026-2013（P0）登出后 token 仍有效**：登录写入随机 `sid`，`events.signOut` 拉黑（Redis/进程内），
  所有鉴权入口校验吊销表；会话与 JWT 有效期 24h → 8h。

#### 中危

- ✅ **FIX-2026-2014 上传链路断裂**：新增 `app/uploads/[...path]/route.ts` 读盘回流（白名单文件名 + nosniff），

- ✅ **FIX-2026-2015 全局重置令牌**：令牌带过期（默认 24h / 最长 7 天）、一次性（用后作废）、

- ✅ **FIX-2026-2016 验证码可程序化识别**：SVG 点阵（path 可查表 100% 还原）→ 服务端光栅化 PNG，
  整体旋转/斜切 + 逐像素位置·尺寸·颜色抖动 + 干扰曲线 + 噪点，响应只含 base64 图片。
- ✅ **FIX-2026-2017 错误出口**：22 个路由的 `catch` 统一改 `handleApiError`（401/403/422/409 不再压成 500），

- ✅ **FIX-2026-2018 登录锁定**：账号维度硬锁（连续失败达阈值锁 30 分钟，换 IP 无效）+ `account_locked` 审计。

#### 功能与体验
