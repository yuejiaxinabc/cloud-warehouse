## 二、更新在哪里体现（文件 → 改动 → 验证）

### 1. 安全复检（FIX-2026-1012）

**验证码真正生效**——原来存储写在 route 内部，`authorize()` 访问不到，攻击者直接 POST callback 就能跳过验证码。

| 位置 | 改动 |
|---|---|
| `src/lib/captcha-store.ts`（新增） | 验证码共享存储，route 与 `authorize()` 共用，一次性消费 |
| `src/lib/auth.ts:52` | `authorize()` 内 `consumeCaptcha()`，服务端强制 |
| `src/app/login/page.tsx` | 不再前端预验，`captchaToken/captchaAnswer` 随 `signIn()` 提交 |
| `src/lib/captcha-font.ts`（新增） | 字形改为 5×7 点阵 `<path>`，响应里不再有 `<text>` 明文 |

**实测**（线上）：
```
不带验证码直接打 callback        → error=验证码参数错误
伪造 captchaToken                → error=验证码已过期，请刷新
有效票据 + 错误答案              → error=验证码错误，票据销毁
同一票据重放                     → error=验证码已过期，请刷新
```

**其他安全项**：

| 位置 | 改动 |
|---|---|
| `src/middleware.ts:157-186` | CSRF 同源判定改用请求真实 `Host`（原用可伪造的 `X-Forwarded-Host`，伪造两者一致即可绕过） |
| `src/middleware.ts:118-124` | `NEXTAUTH_SECRET` 弱密钥 → 全站 503（fail-closed），配套 `src/lib/env-guard.ts`、`src/instrumentation.ts` |
| `src/app/api/upload/route.ts:23` | 文件类型按**魔数**嗅探，扩展名只从白名单推导，显式拒绝 SVG，文件名 `crypto.randomBytes` |
| `src/lib/api-token.ts` | Token 生成 `Math.random()` → `crypto.randomBytes`；校验 fail-open → **fail-closed**；比较用 `timingSafeEqual` |
| `src/lib/auth.ts:22-27,103-113` | 登录失败改为 **IP + 账号双维度**限速（10 次/5 分钟、8 次/15 分钟），账号维度指数退避不硬锁，避免被用来打死管理员 |
| `src/lib/auth.ts:103` | 用户不存在也跑一次 dummy bcrypt，消除响应时间枚举 |
| `src/lib/auth.ts:152-168` | 会话 Cookie 显式声明 `httpOnly/sameSite/secure`，按 `NEXTAUTH_URL` 协议决定 `__Secure-` 前缀 |
| `src/lib/auth.ts:205` | `hasRole()` 大小写不敏感（原 `'ADMIN'` 大写 vs 库里 `'admin'` 小写，潜伏缺陷） |
| `src/lib/redis.ts` | 补 `error` 监听——原来 ioredis 连不上会以未捕获异常打挂进程 |
| `next.config.js` | 关闭 `X-Powered-By`，启用 `instrumentationHook` |

## 四、上线时一并修复的数据库问题（重要）

审计复测时发现线上 `Role` 表为 **0 行**，而 `user_roles` 有 6 条记录指向 role_id 1–6（外键存在但数据被清空），导致所有账号登录都会抛 Prisma 错误。已在服务器补回：

```sql
INSERT INTO `Role` (id, name, code, status, created_at, updated_at) VALUES
(1,'系统管理员','admin',1,NOW(3),NOW(3)),
(2,'仓库主管','wh_manager',1,NOW(3),NOW(3)),
(3,'仓管员','wh_keeper',1,NOW(3),NOW(3)),
(4,'采购员','buyer',1,NOW(3),NOW(3)),
(5,'销售员','sales',1,NOW(3),NOW(3)),
(6,'审计员','auditor',1,NOW(3),NOW(3));
```

**修复后实测**：

```
admin 登录                 → {"url":"http://146.56.204.119"}   ✅
/api/auth/session          → user=系统管理员, roles=['admin']
/api/products              → 200 success=true
/api/users                 → 200 success=true (1431B)
/（工作台）                → 200
/products /products/io /inventory /inventory/analysis
/warehouse /shelf-map /stock-in /stock-out /serial /export /settings /logs
                           → 全部 200
```

> ⚠️ 该表被清空的原因需排查（`prisma/seed.ts` 旧版用 `create` 而非 `upsert`，重复执行会因唯一键冲突中断，中断后可能出现角色缺失）。新版 seed 已全部改 `upsert`，可安全重复执行。
