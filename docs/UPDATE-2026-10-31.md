## 一、高危项

| 编号 | 问题 | 修法 | 代码位置 |
|------|------|------|----------|
| H1 | 负数量入库/出库可建单并过账 → 负库存、成本被污染至 22.5 亿 | ① 建单侧统一走 `assertPositiveQty`（>0、≤1e6、≤3 位小数）与 `assertNonNegativePrice`（0~1e8）；② **过账事务内二次校验**，历史草稿里的负数也拦得住；③ 加权平均成本在 `onHand < 0` 时**不再套公式**，直接用本次入库价重建基准成本并写 `COST_REBUILD` 审计日志 | `src/lib/qty-guard.ts`、`src/app/api/stock-in/route.ts`、`src/app/api/stock-out/route.ts`、`src/services/stock-in.service.ts` |
| H2 | 并发重复过账（check-then-act），5 连发 2 次成功、库存 +4 | ① 事务第一句 `SELECT id FROM inbound_orders WHERE id=? FOR UPDATE` 行锁（出库同理）；② 收尾用条件更新 `updateMany({where:{id,status:'DRAFT'}})`，影响行数 0 直接 409 | `src/lib/order-lock.ts`、`src/services/stock-in.service.ts`、`src/services/stock-out.service.ts` |
| H3 | 登出后旧 token 仍可用满 24h | ① 登录时写入随机 `sid`；② NextAuth `events.signOut` 把 sid 拉黑（Redis 优先、进程内兜底）；③ 所有鉴权入口（requireLogin/requirePermission/requireAuth/requireAdmin）校验吊销表，失效即 401；④ 会话与 JWT 有效期 24h → 8h | `src/lib/session-revocation.ts`、`src/lib/auth.ts`、`src/lib/auth-guard.ts` |

## 六、验证方式

```bash
# 0) 依赖与数据库（本版无 schema 变更，无需迁移）
npm ci

# 1) 类型检查（仓库开启 ignoreBuildErrors，仍需保证无新增错误）
npx tsc --noEmit | grep -E 'src/(lib|services|app/api)' || echo "改动区域无类型错误"

# 2) 构建
npm run build

# 3) 手工回归（建议按顺序）
#   H2：同一草稿单并发 5 次 POST /api/stock-in/{id}/post → 期望 [200,400,400,400,400]，库存只 +1 次
#   H1：planQty=-5 建单 → 期望 400「第 1 行入库数量必须大于 0」
#   H3：登录 → 记 token → signout → 用旧 token GET /api/settings/profile → 期望 401
#   M4：上传 PNG → GET 返回的 /uploads/<name> → 期望 200 image/png
#   M5：check-token → 记 expiresAt → 重置一次密码 → check-token 期望 hasToken=false
#   M6：GET /api/auth/captcha → 响应只含 {token,image}（base64 PNG），无 svg 字段
#   F6：GET /api/products?sort=-name → 顺序与默认相反
#   F5：GET /api/stock-in?type=RETURN → 只返回退货类型
```
