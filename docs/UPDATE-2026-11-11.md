## 二、验证结果（本地隔离副本，代码与工作区一致）

- `npm install` 在本机直装失败 3 次：lockfile 里的 265 个地址指向 `http://mirrors.tencentyun.com/npm`，该镜像在本机上 socket hang up；改用隔离副本、把 lockfile 地址换成官方 registry 后，`@prisma/engines` postinstall 下载引擎二进制仍 ECONNRESET。最终用 `--ignore-scripts` 安装 + `PRISMA_BINARIES_MIRROR=https://registry.npmmirror.com/-/binary/prisma` 生成 Prisma Client 后验证通过。**工作区本身的 `package-lock.json` 未动、未装 `node_modules`**（如需在用户自己的电脑上装依赖，直接 `npm install --legacy-peer-deps` 即可，服务器上已有依赖，不受影响）。
- `npx tsc --noEmit`：**34 个报错，全部是接手前就有的**（逐项核对：bom/transfers/reports 页的 onChange 类型错、`product.service` / `inventory.service` 的 Prisma 输入类型错、alert.service 的 bigint、mailer 缺 `@types/nodemailer`、charts 变量名等，均不在本次改动行内；A/B/C 改动文件本身 0 个新增报错；协调员改的 `(dashboard)/layout.tsx` 与 `AntdRegistry.tsx` 0 报错）。`next.config.js` 本来就有 `typescript: { ignoreBuildErrors: true }`，构建不受影响；要清零这 34 个需另排期逐项修，不在 1.2.4 范围内。
- `npm run build`：**通过（exit 0）**，全部路由正常生成（/login、/terms、/privacy、/screen、/settings、/setup、/bom、/inventory、/reports/* 等）。

## 三、未做项及原因

1. **脏数据清理——只给清单，不在本地删库**（本地无数据库连接，且删库不可逆）。上线前请先备份，再在服务器上用以下只读 SQL 自查，确认后手工处理：
   ```sql
   -- 负库存 / 负可用量
   SELECT * FROM inventory WHERE onHand < 0 OR locked < 0 OR locked > onHand;
   -- 混放货位（应为 0，触发器已兜底）
   SELECT locationId, COUNT(DISTINCT productId) c FROM location_stocks WHERE quantity > 0 GROUP BY locationId HAVING c > 1;
   -- 金额为 0 但数量非 0 的收发存行
   SELECT * FROM stock_ledger WHERE amount = 0 AND qty <> 0 LIMIT 50;
   -- 无批次号的效期商品入库明细
   SELECT * FROM stock_in_items WHERE batchNo IS NULL AND productId IN (SELECT id FROM products WHERE shelfLifeDays > 0) LIMIT 50;
   ```
   另有现成脚本 `scripts/cleanup-uploads.mjs`（清理孤儿上传文件），部署时可顺带跑。
2. **HTTPS 未启用**：只有 IP 没有域名，Let's Encrypt 无法为纯 IP 签发，本地不做；绑好域名后按 v1.2.3 文档执行 certbot 并改 `.env` 的 `NEXTAUTH_URL`。
3. **前端各页对新格式化工具的全面接线未做**：B 已提供 `formatMoney` / `formatQty` / `formatDate` 等工具，但 dashboard 各页、大屏的调用点替换不在 B 的文件范围内；导出提示文案在页面层，需接 `X-Export-Count` 响应头或 `exportedCount` 字段拼提示，不要再硬编码。
4. **`BarcodeScanner` 内部无超时兜底未做**：组件本身不在 C 的文件范围；但 C 已让手动输入框始终可见、修了反复重启的根因，用户不再会被卡住。
5. **`export_tasks` 表无条数字段**：条数目前靠返回值/响应头/文件名传递，持久化按任务查条数需加列迁移。
6. **页面级栅格未全量迁移**：A 提供了 `.yc-kpi-grid` / `.yc-card-grid` 与 `DataTable` 的 `hideOnMobile` 列开关，各业务页自身的 `Row/Col` 与列定义需后续逐页标记次要列。
7. **DataTable 的 `onChange` 类型错是旧问题**：bom/transfers/reports 等页传 `onChange={(page, size) => ...}`，与 Antd Table 的 `onChange(pagination, filters, sorter)` 签名不符（HEAD 时代就已存在，运行时分页回调实际走的是 `pagination.onChange: onPageChange`，页面传的 `onChange` 会被透传给 Antd Table，行为需后续逐页改成 `onPageChange`）。

# v1.2.3 更新说明（2026-11-11 · 数据权限 / 组织 / 字典 / 登录日志）

> 基线 v1.2.2。设计参考开源脚手架 scaffold-master（MIT License，作者 wbr664393425-lgtm）的
> data_scope / sys_dept / sys_dict / sys_login_log 思路，按云仓 Prisma + Next.js 栈重写；未引入 Java/Vue 代码。

## 一、新增能力

| 模块 | 能力 | 代码位置 |
| --- | --- | --- |
| 数据权限 | 角色档位：全部 / 本部门及以下 / 本部门 / 指定组织 / 仅本人经手；多角色取最宽 | `src/lib/data-scope.ts`、`prisma/schema.prisma`(Role) |
| 组织架构 | 祖先链 `ancestors`（",1,2,"）+ `level`，换上级自动重算子树 | `src/app/api/organizations/route.ts` |
| 仓库归属 | `Warehouse.orgId`，数据权限据此收敛可见仓库 | `src/app/api/warehouse/route.ts`、仓库页 |
| 用户归属 | `User.orgId` 可在用户弹窗里选择 | `src/app/api/users/route.ts`、设置页 |
| 字典中心 | `dict_types` / `dict_data` + `/dict` 页面 + 5 个内置字典 | `src/app/api/dicts/**`、`(dashboard)/dict/page.tsx` |
| 登录日志 | `login_logs` 六类事件 + 查询接口 + 日志页标签 | `src/lib/auth.ts`、`api/login-logs`、`logs/page.tsx` |

## 二、接口变更

- 新增 `GET/POST/PUT/DELETE /api/organizations`（读：登录即可；写：`user:manage`）
- 新增 `GET /api/dicts`、`POST/PUT/DELETE /api/dicts`（写：管理员）、`GET/POST/PUT/DELETE /api/dicts/data`
- 新增 `GET /api/login-logs`（`audit:view`）
- `GET/PUT /api/roles`：多出 `dataScope`、`dataScopeOrgIds`
- `GET/POST/PUT /api/users`：新增可写字段 `orgId`
- `GET/POST/PUT /api/warehouse`：新增可写字段 `orgId`，列表多返回 `orgId`、`organization.name`
- 读面五件套（库存/入库/出库/盘点/调拨）响应 `data.scope = { mode, label, warehouseCount }`

## 三、部署步骤

```bash
# 1. 代码
rsync -a --exclude node_modules --exclude .next --exclude '.env*' --exclude 'public/uploads' \
  ./ root@<host>:/opt/cloud-warehouse/

# 2. 依赖与客户端
cd /opt/cloud-warehouse && npm install --legacy-peer-deps && npx prisma generate

# 3. 表结构（三张新表 + 六个新列）
npx prisma db push

# 4. 历史组织回填祖先链（幂等）
node scripts/backfill-org-scope.mjs

# 5. 内置字典（幂等）
npx ts-node --compiler-options '{"module":"CommonJS"}' prisma/seed-dicts.ts

# 6. 构建 + 重启
NODE_OPTIONS=--max-old-space-size=2048 npm run build
systemctl restart cloud-warehouse
```

若环境不允许 Prisma 直连改表，用 `deploy/migrations/v1.2.3.sql` 手工执行，再跑第 4、5 步。

## 四、上线后自检

1. 设置 → 角色管理：新建角色选「本部门」，保存后表格显示数据范围标签；
2. 设置 → 用户管理：给测试账号指定归属组织；
3. 仓库页：给某个仓库设置归属组织（不设置的仓库只有「全部数据」角色能看到）；
4. 用该账号登录：库存/入库/出库列表只剩本部门仓库的数据，直接改 URL 打开别部门单据返回 403；
5. 字典管理：能看到 5 个系统字典，改动后业务下拉同步；
6. 日志页 → 登录日志：能看到刚才几次登录/失败记录，含 IP 与客户端。
